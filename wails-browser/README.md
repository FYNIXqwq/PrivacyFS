# PrivacyFS Wails 3 目录浏览器

这是独立的新工具，当前只实现第一步：**选择目录 → 扫描名称与目录关系 → 浏览结构**。没有 AI、隐私分类、重命名或导出功能。

## 启动

- 普通启动：仓库根目录 `PrivacyFS-Wails.vbs`。
- NTFS 卷读取通常需要管理员权限：手动运行 `PrivacyFS-Wails-Admin.vbs`，由 Windows UAC 请求授权。
- 也可直接打开 `bin/PrivacyFS-Browser.exe`。此程序是本地构建的 Windows x64 可执行文件，未做代码签名。

点击“选择目录…”会自动开始扫描；也可以输入路径后点击“开始扫描”。左侧展开目录，右侧双击文件夹进入，面包屑可返回上级。两侧均为连续滚动的完整逻辑列表，没有分页或“加载更多”按钮。左侧支持全部展开、全部折叠；右侧显示当前目录总项数，可输入序号直接跳转。滚轮、方向键、Page Up/Down、Home/End 和滚动条均可浏览。

界面采用虚拟滚动：完整索引和层级保留在 Go 后端，只把当前视口附近的名称交给界面绘制。百万条目也无需创建百万个网页节点；滚动条覆盖完整列表，末尾条目可以直接访问。超大列表使用逻辑滚动坐标，避开浏览器像素高度上限，滚轮仍按实际行高移动。

三种读取方式：

| 方式 | 行为 |
|---|---|
| NTFS 优先 | 尝试 NTFS 元数据接口；权限、文件系统或接口不可用且尚未读入索引时回退普通遍历，页面显示回退原因 |
| 仅 NTFS | 失败直接显示原因，不改用普通遍历 |
| 普通目录遍历 | 可以边扫描边浏览，适合小目录或无卷读取权限的情况 |

扫描结束前结构可能未齐全；结束后界面会刷新。停止保留已读取部分，失败、取消与完整读取明确区分。刷新按钮刷新当前内存视图；文件系统发生变化后需要重新扫描。

## 实现与边界

- Wails **v3.0.0-beta.14**，Go 后端，WebView2 界面；前端使用内嵌 HTML/CSS/JavaScript 和 Wails 自带 runtime，不需要 npm 或独立服务器。
- NTFS 使用 `FSCTL_ENUM_USN_DATA` 读取名称元数据。文件与父目录关系在读入时建立，不进行 Python/SQLite 的二次全树整理，也不将全量结果发送给前端。
- 紧凑节点为 32 字节，名称放在共享 UTF-8 字节区，目录查询使用父 ID 索引与链表。当前目录缓存紧凑条目 ID，展开树缓存 ID 与深度；滚动时直接读取任意位置，不从首条重复遍历，也不重复复制全量名称。目录树不遍历同级文件。会话 ID、读取范围和所选目录范围都在 Go 端校验。
- 首次打开大目录或全部展开时需要生成对应 ID 视图，耗时随条目数量增长；后续滚动复用视图。扫描有变化或展开状态变化时重建相应视图，缓存计入内存预算。
- NTFS 选子目录时仍读取所在卷的记录，顶部计数是**卷级计数**，不是所选子树数量。页面只展示所选目录范围。
- 这是名称元数据视图，可能缺少硬链接别名；不逐项校验 ACL，也不保证扫描期间发生变化后的快照一致性。它不是隐私审计结果。
- 普通遍历不跟随链接/重解析目录；NTFS 的链接名称可以显示，但不会展开。标记为 `.privacyfs-state.json` 的私有状态目录不展开。
- 不读取源文件正文，不修改源文件内容。索引在内存中，不主动生成文件名清单缓存；不承诺安全擦除内存或阻止操作系统换页。
- 内存预算按开始扫描时可用物理内存的约三分之一估算，最大 4 GiB。预算不是进程 RSS 硬限制；触及时停止并显示部分状态，不悄悄截断成成功。可用普通遍历检查较小目录。
- 当前交付验证平台为 Windows x64；不声称已经完成其它系统的 GUI 验证。

## 构建与开发

需要 Go **1.25+**、对应版本的 Wails 3 CLI 和 WebView2 Runtime。本机使用 Go 1.26.7；`wails3 doctor` 已确认开发依赖就绪。

```powershell
cd C:\PrivacyFS\wails-browser
.\build.ps1
# 已缓存模块时可离线构建
.\build.ps1 -Offline
# 开发运行（会打开新工具窗口）
go run .
# 测试
go test -tags production ./...
go vet ./...
```

构建结果为 `bin/PrivacyFS-Browser.exe`。资源、前端与 runtime 均嵌入可执行文件。`go.mod/go.sum` 固定依赖，构建不会打包仓库中的 GGUF、Python 环境、映射数据库或用户文件。

## 验证记录

- Go 回归涵盖：晚到的父记录、子目录范围、游标校验、分页完整性、目录查询不扫描文件、私有标记、重解析链接、原件字节保持、会话切换、运行中取消、失败与回退分界、内存不足显式失败、USN 边界和 Unicode、内嵌资源及服务名称。
- 新增回归覆盖百万条目随机位置读取、末尾访问、视图更新、完整层级全部展开与折叠、私有目录和链接边界，以及 1200 万行滚动坐标计算。
- 隔离无头页面检查使用合成数据，在两种窗口尺寸验证百万项末尾跳转、精确滚轮移动、万级目录树末尾、折叠、有限 DOM 节点数、文件名安全文本渲染、目录进入及面包屑返回。没有通过自动化操作用户的真实扫描窗口；原生目录选择框及真实卷吞吐仍由用户实际测试。
- 合成 100 万文件与 1000 个目录的纯 Go 索引构建基准，约 **0.175 秒**，索引估算约 **46.6 MiB**。这不包含 NTFS 读取、USN 解码、界面通信或绘制；不能当作真实 C 盘扫描时间，分配量也不是进程峰值内存。

```powershell
go test ./internal/browser -run '^$' -bench BenchmarkIndexMillion -benchtime=1x -benchmem
```

验证命令还包括 `node --test web/virtual.test.mjs`。原仓库回归报告在 `.review/wails-repo-tests.xml`；真实卷读取速度不能由合成页面或内存索引测试推断。
